# Project Instructions

## General
- Inspect the existing code before making assumptions.
- Preserve the existing design system unless explicitly instructed otherwise.
- Prefer modifying existing components over creating duplicates.
- Keep mobile and desktop layouts responsive.
- Do not expose credentials, API keys, or secrets.

## Git workflow
- Never merge directly to main.
- Never deploy production changes without explicit approval.
- Before committing, show:
  1. files changed
  2. summary of changes
  3. tests performed
  4. any known risks
- Wait for approval before pushing or merging.

## Development
- Run the relevant build/test command after substantial changes.
- Fix TypeScript/lint/build errors created by your changes.
- Do not rewrite unrelated code.

## User preference
- Implement requested changes rather than only explaining how.
- Ask before destructive operations.
- Keep solutions simple and production-ready.
